# Architecture and product decisions

This log supplements the detailed records in `docs/adr/`.

## Accepted baseline

| ID    | Decision                                                                                                              | Rationale                                                                                                        | Status   |
| ----- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------- |
| D-001 | React + Vite + TypeScript for the web client; preserve the existing UI.                                               | It is already implemented and builds; migration would add risk without product value.                            | Accepted |
| D-002 | Node.js + Express + TypeScript for a separate `apps/server` API.                                                      | Matches the supplied SRS and keeps API/security logic server-side.                                               | Accepted |
| D-003 | PostgreSQL + pgvector, not Qdrant, for the initial data/vector store.                                                 | One local service and unified authorization/query model. Database implementation belongs to Phase 2.             | Accepted |
| D-004 | Ollama is the only default AI path; no automatic hosted fallback.                                                     | Protects user data and avoids paid-service dependency. Hosted adapters require explicit later opt-in.            | Accepted |
| D-005 | Local development uses filesystem uploads outside the public web root.                                                | Simple local MVP; object storage adapter is later work.                                                          | Accepted |
| D-006 | Do not add OCR, Redis, integrations, or auth implementation in Phase 0/1.                                             | Defer until supported by phase dependencies and workload.                                                        | Accepted |
| D-007 | Runtime observed on 2026-10-18: Node 24.12.0, npm 11.6.2, 8 GB RAM, 4 CPU cores; Docker and Ollama not found on PATH. | Sets constraints for local model and database validation; Ollama model selection must be tested on this machine. | Observed |
| D-008 | Existing workspace directory had no Git repository at audit time.                                                     | Initialize Git on `main` without committing user files; user can configure identity/remote and commit.           | Accepted |

## Resolved decisions

| ID    | Decision                                                                                                                                                                                                                                                                               | Rationale                                                                                                                                               | Status   |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| D-009 | `express-session` + `bcryptjs` for password hashing; `connect-pg-simple` for PostgreSQL session store.                                                                                                                                                                                 | Established, well-maintained Express ecosystem libraries; keeps sessions server-side and ties them to the same PostgreSQL instance used by pgvector.    | Accepted |
| D-010 | Secure, HttpOnly, SameSite=Lax session cookie in production; cookie lifetime 7 days; refresh via login re-validation.                                                                                                                                                                  | Matches SRS security requirements (secure cookies, session management) and keeps implementation simple for MVP.                                         | Accepted |
| D-011 | CSRF protection via double-submit cookie pattern for state-changing routes (login, logout, upload, delete, etc.).                                                                                                                                                                      | Protects session cookie authentication from cross-site request forgery without adding a separate CSRF dependency.                                       | Accepted |
| D-012 | Account reset: password-reset token stored as a hashed, single-use, time-limited (1 hour) row; no email sending in MVP, token returned via API for local dev flow.                                                                                                                     | Avoids external email provider dependency in Phase 2; secure enough for local MVP with token expiration and one-time use.                               | Accepted |
| D-013 | PostgreSQL connection via `pg` (node-postgres) connection pool; `DATABASE_URL` from `.env`; migrations run as SQL files applied at startup in development.                                                                                                                             | Uses the already-selected PostgreSQL + pgvector stack; avoids ORM complexity for the MVP schema.                                                        | Accepted |
| D-014 | Supported upload file types: PDF (.pdf), TXT (.txt), CSV (.csv) only. MIME validation: `application/pdf`, `text/plain`, `text/csv`. Max file size: 15 MB (from `MAX_UPLOAD_MB`). Per-workspace total upload quota: 500 MB.                                                             | Matches SRS MVP scope ("PDF, TXT, CSV, and only those image types with an implemented extraction path"); keeps the upload surface narrow and scannable. | Accepted |
| D-015 | Uploads stored under `UPLOAD_DIR` (`./data/uploads`) outside the public web root, addressed by random `crypto.randomBytes` storage keys; new directories/files use restrictive permissions. Original filename is metadata only; no user-controlled path reaches filesystem operations. | Satisfies SRS/D-005 (filesystem uploads outside public web root, random keys, prevent traversal).                                                       | Accepted |
| D-016 | Document processing status values: `uploaded`, `processing`, `completed`, `failed`. Status stored in `documents` table; deletion removes both the stored file and the document row.                                                                                                    | Provides visible upload lifecycle for the UI; simple state machine sufficient for Phase 3.                                                              | Accepted |

## Remaining open decisions

- Phase 3 verification: PostgreSQL/pgvector must be installed or Docker enabled before live upload persistence, cross-workspace authorization, deletion, and quota integration checks can be completed. Core document routes and DB-independent tests are implemented.
- Phase 4/8: supported invoice/CSV schema, timezone/currency/refund handling, import undo behavior.
- Phase 5: exact Ollama chat and embedding model versions after installation/performance validation.
- Phase 14: deployment host and costs; no hosted free-tier assumptions are accepted.
